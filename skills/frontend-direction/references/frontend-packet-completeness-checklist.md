# Packet Completion

Before handing off a newly finalized packet:

- Version-2 packet.md marker, packet.json schema, design_source manifest, runtime_evidence and references follow the [finalization recipe](packet-finalization.md). The read-only check passes; handoff carries exact entry, revision, descriptor SHA-256, human approval reference, status and accepted limits.
- Follow-on entry links settled approved spec/context; standalone entry contains the sufficient brief and original design/implementation scope.
- Status is `approved`, or `approved-with-degraded-evidence` with explicit approval of listed limitations. Unresolved required direction stays `required-pending`.
- Brownfield notes distinguish constraints/anchors from problems/freedom and identify current versus historical evidence.
- Screen index names implementation-shaping screens/states, setup, viewports, observable acceptance, exact references/intents, and actual evidence revision. Earlier checks and missing proof are explicit.
- Selected concept/version, material refinement and human selection are recorded when exploration ran.
- Selected design source is locally recoverable. Paper retains provenance, structure, computed styles, frozen resolved tokens, assets, approved copy/state mapping and component/source mappings. Runtime design retains actual code; references-only records the actual scoped omission decision.
- Required runtime IDs resolve once to recorded results and inventoried JSON records. Records carry the seven-field runtime handoff, matching source identity, dependency setup, recoverable code or verified immutable recovery evidence, and retained dirty changes. Empty required checks have a substantive scoped reason. Failed required checks block; unavailable required checks retain their ID/record and name the exact explicitly accepted degraded limitation.
- Every binding local path is contained and inventoried, including extraction, tokens, assets, provenance, mappings, runtime records and recovery files. External locators do not exempt local paths. Captures name intent, state, viewport, actual source version and supersession; uncaptured states retain concrete setup and verification status.
- Sensitive standalone details have actual-component demonstration or explicitly accepted limits. Visual approval, functional checks and observed human tasks are separate; unavailable human observation is recorded honestly.
- Every binding target's intent/scope and final approval are clear. Missing intent blocks dependent visual changes; no duplicate approval ceremony for a classification already covered by packet approval.
- Copy source, responsive/accessibility constraints, concrete component mapping and production verification expectations are named. Validate visual/interaction quality separately from the file check.
- Historical packets remain byte-identical at their original paths as reference material only. Version 1, missing versions and unsupported versions block implementation. New delivery establishes its own v2 evidence and approval without migration or fallback.
- Return to the invoking workflow, or complete/continue the standalone request within its original authorization. No automatic standalone delivery router.
