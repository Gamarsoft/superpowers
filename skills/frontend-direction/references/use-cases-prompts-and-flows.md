# Example: Standalone Screen Improvement

“Use frontend-direction to improve this customer detail screen. Operators cannot find the balance or tell which account scope is active. Keep our brand and app shell; preserve supplied behavior. Explore the design before production integration.”

Inspect the target, fill the small brief from known facts, and identify task objectives. Because account scope and balance comparison are unresolved, compose one Paper recommendation using supported facts and representative content. Add a comparison only if a consequential disclosure or density tradeoff remains. Apply task-to-layout and relevant design knowledge, then prove component-sensitive details in a small actual-app slice, including relevant narrow and keyboard states. In the existing final review, record visual approval, functional checks and human task observations separately. Retain the final approved target and packet. Continue implementation only when the original request includes it. Use image generation for authorized assets or deliberate brand exploration; explicit image-based concept requests follow the scoped override in visual exploration.

A follow-on from brainstorming enters the same loop with an already settled brief/spec. A supplied approved target or mechanical correction skips unresolved-direction exploration. Read the entry table in SKILL.md for those conditions.
