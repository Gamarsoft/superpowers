# Frontend Direction Phase

Brainstorming uses this gate when substantial unresolved screens, layout or interactions shape implementation. Skip exploration for mechanical changes or a current approved target.

The separate frontend-direction session consumes the approved spec/follow-on and retains brand/shell and constraints. It chooses [exploration by the unresolved decision](visual-exploration.md): Paper for substantial composition, focused actual-app slices for behavior and component-sensitive feasibility, and image assets or deliberate brand exploration when authorized. Explicit medium requests retain their scoped override. It compares task use, refines the selected direction and demonstrates sensitive details in actual components. Version-2 final packets use the [canonical finalization contract](packet-finalization.md), carrying packet.md, packet.json and checked revision/descriptor identity back to the invoking workflow. The durable packet includes exact approved targets, intent, source/launch/state notes, final captures, copy and separate visual, functional and human-task evidence. Temporary brainstorming companion sketches remain decision context.

Status: `not-required` for out-of-scope direction; `required-pending` while required decisions remain; `approved` for the final accepted packet; `approved-with-degraded-evidence` only after explicit approval of its limits. Return the approved packet to brainstorming's delivery router. This reference does not select a route or create an adapter.

For a direct screen-improvement request, use frontend-direction's standalone entry instead; no full brainstorming flow or pre-existing spec is needed.
