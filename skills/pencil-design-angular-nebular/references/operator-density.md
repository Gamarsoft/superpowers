# Operator Density

## Principle

Operational screens are allowed to be dense.
The goal is **high-throughput legibility**, not consumer minimalism.

## Preserve

- key counts
- statuses and warnings
- assignment actions
- filter visibility
- action priority
- split views or two-panel workflows when they serve throughput

## Improve carefully

You can improve:

- spacing consistency
- scan paths
- label clarity
- grouping of actions
- status contrast
- row/card readability

You should not improve by hiding critical information behind too many taps or disclosures.

## Review questions

- what information does the operator need visible before acting?
- what can become secondary without harming throughput?
- did the design remove urgency cues or runtime state cues?
- is the flow still fast for an experienced operator?
