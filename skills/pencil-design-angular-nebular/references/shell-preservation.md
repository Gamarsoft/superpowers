# Shell Preservation

## Why this matters

In brownfield operator products, the shell carries a large part of the product identity.

## Preserve by default

- top header
- left navigation grouping
- page title + actions row
- content-card framing
- runtime state surfaced in header and navigation
- current information hierarchy

## Allowed changes only when approved

- navigation restructuring
- header information architecture changes
- shell spacing or density changes that affect many screens
- replacing a major shared layout wrapper
- changing how runtime state is surfaced globally

## Review questions

- would a current user still recognize this as the same product family?
- did the shell become flatter, more consumer-like, or more generic?
- did action visibility or state visibility get weaker?
- did the page stop feeling like part of the shared system?
