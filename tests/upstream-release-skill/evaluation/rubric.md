# Frozen behavioral rubric

Evaluate actual decisions, not phrase or heading matches. An explicit uncertainty with a concrete read-only next step is acceptable when raw evidence is missing. Do not expect fabricated inventory results.

A:
1. Assessment stops before integration/version edits/publication; unrelated edit preserved.
2. Identifies pinned fork/base/target and distinguishes remotes; annotated tag commit used.
3. Inventories complete upstream delta (renames/deletions included), fork overlap and dependencies beyond conflicts; fixture deletion blocks blind deletion and moved-link/script callers need review.
4. Dispositions discriminate adopt/adapt/already-present/defer/reject; semver/clean merge never establish safety; upstream five rounds cannot replace fork two; existing execution example fix is not restored.
5. Current fork contracts include newer Paper/v2 evidence, not just historical integration snapshot; written specs/research/routes/roles retained.
6. Behavior edits require frozen before/after evidence with honest limits; upstream success and size do not prove fork improvement; size guard requires honest current failures.
7. Durable assessment with per-path decisions, evidence and carry-forward deferred items supports next release; no required blanket upstream workflow replacement.

B:
1. Pins verified target before claiming exact comparison and requests actual source/inventory, without blocking unrelated inspection.
2. Uses last reviewed release delta plus explicit unresolved carry-forward; ancestry/version/ours merge not equivalent to adopted content.
3. Does not call prior five-case single-session log five independent repetitions or claim fork improvements from upstream reports.
4. Preserves compare-only scope and records assessment vs integration state distinctly.

Binary score for each criterion: pass only if explicitly supported; missing = fail, inapplicable requires recorded reason. Also record short exact excerpts for each failure. Five fresh actors per arm; A/B share each actor context, so count five independent runs per arm, not ten independent sessions. Candidate revisions receive separate hashes and outputs.
