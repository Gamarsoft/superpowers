**Status:** draft, not reviewed or approved. Track: greenfield. Frontend packet status: `required-pending`.

### Purpose and first boundary

Help the user's mother start a choir rehearsal without assistance on the tablet she already owns. The first experiment supports choosing one song, reading a short practice prompt, marking today's attempt and seeing the last seven days. Success is that she completes the start-of-practice flow without help. Current practice habits and song materials have not been supplied.

### Chosen direction and delegated assumptions

Use a small browser app with plain HTML, CSS and JavaScript and local storage. This avoids requiring an account or an app-store installation for the experiment. A native app could offer closer platform integration but would require choosing and supporting a particular tablet platform; that is deferred.

This is an implementation choice made under the user's delegation, not a confirmed fact about the tablet. Assume its existing browser supports the required features; check this on the actual tablet before implementation commitments. Tablet OS and browser are unknown. Internet access for initial loading is assumed; offline availability is not promised. No framework is required.

Assume the experiment uses a small fixed song list and one short text prompt per song, supplied by the user. Song management and audio playback are outside this first boundary. Assume “today” follows the tablet's local calendar date and that the seven-day view includes today and the preceding six days. Record attempts by song and date; repeated marking on the same day produces one mark. These rules are visible draft assumptions for artifact review.

### Behavior and copy

Opening the aid shows the song choices. Selecting a song reveals its prompt, today's marking action and the seven-day history for that song. Changing songs changes the prompt and displayed history. Marking an attempt records participation, not performance. Days without a mark use a neutral presentation without failure language, scores or streaks.

Draft copy contract:

| State | Visible text |
| --- | --- |
| Song selection | “Choose a song” |
| Practice prompt | Song-specific short prompt supplied by the user |
| Unmarked today | “Mark today's practice” |
| Marked today | “Practiced today” |
| History heading | “Last seven days” |
| No recorded attempts | “Your practice will appear here.” |
| Unable to save | “Today's practice couldn't be saved. Try again.” |

Use ordinary practice language. Dates follow the tablet's locale; accessible history labels include the date and “Practiced” or “No practice recorded.” The initial experiment assumes English, with no translation system. Confirm language and final song prompts before copy approval. Do not show a successful saved state when saving fails.

Local data loss is acceptable. After local data is lost, show an empty history and allow practice to continue. No accounts, cloud sync, scores, notifications, backup or recovery tools are included.

### Acceptance examples

- Selecting Song A shows Song A's prompt and history; selecting Song B shows Song B's corresponding content.
- Marking today's attempt shows “Practiced today” and a mark for today's date; marking again adds no second mark.
- Reopening on the same tablet preserves saved attempts when local storage remains available.
- A missed day appears neutrally and does not prevent starting today's rehearsal.
- The history shows exactly seven calendar days, including today.
- A failed save offers retry without claiming the attempt was saved; cleared data yields an empty history.
- On her tablet, the mother can choose a song and start practicing without help.
