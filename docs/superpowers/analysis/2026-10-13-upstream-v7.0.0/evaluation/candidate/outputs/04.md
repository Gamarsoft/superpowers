**Purpose and success.** Help the user's mother start a rehearsal independently on the tablet she already owns. The first experiment succeeds when she can choose a song, understand its practice prompt and start without help.

**User decisions.** One song at a time, a short practice prompt, a way to mark today's attempt, and the last seven days of attempts. Calm language must avoid implying failure after a missed day. No accounts, cloud sync, scores or notifications. Local data loss is acceptable for this experiment.

**Delegated agent calls.** Use a tablet browser page built with HTML, CSS and plain JavaScript, with attempts saved locally in that browser. This keeps the first experiment small and avoids a platform-specific installation. It gives up native packaging and cross-device continuity. This is my choice, not a platform decision made by the user.

**Visible assumptions.** Her tablet has a usable browser and local storage; compatibility must be checked on that tablet before delivery. A small supplied song list and short prompt for each song are enough; composing a song library is outside this slice. “Today” means the tablet's local calendar day. The seven-day view includes today and the preceding six days, for the selected song. These are agent defaults for review, not established user requirements.

**Behavior and states.** Choose a song, read its prompt, practice, then select “Mark today's attempt.” Repeating the action records only one attempt for that song that day. Show “Attempt recorded today” after saving. Switching songs updates the prompt and history. Days without a record say “No attempt recorded”; do not show streaks, penalties or failure language. The empty history invites “Try a short practice today.” If saving fails, retain the current prompt and show “Couldn't save today's attempt. Please try again.” Never claim a successful save when it failed. Losing local records returns the history to its empty state.

**Boundary and validation.** Verify choosing and switching songs, marking an attempt, repeating the mark, reopening with saved history, a date change, an empty history and a failed save. For example: marking a song twice today shows one recorded day; skipping yesterday leaves a neutral unrecorded day; reopening restores attempts while the browser retains the data. Validate the primary journey on her actual tablet without assistance.
