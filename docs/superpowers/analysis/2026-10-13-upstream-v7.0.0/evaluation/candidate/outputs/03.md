# Choir practice aid

### Purpose and first boundary

Help the user's mother start a rehearsal independently on her existing tablet. The first experiment supports choosing one song, reading a short practice prompt, marking today's attempt and seeing the last seven days. Success is starting a rehearsal without help.

### Decisions and assumptions

**User decisions:** personal use on the existing tablet; calm tone; no accounts, cloud sync, scores or notifications; local data loss is acceptable. A missed day must not imply failure.

**Delegated agent call:** deliver a small browser application using HTML, CSS and JavaScript, with local browser storage. This avoids installation and framework overhead for the experiment. It gives up cloud recovery and reliable cross-device continuity, which are outside scope.

**Assumptions to verify before implementation:** the tablet has a browser that supports the application and local storage. Its operating system and browser are unknown; this choice is conditional on checking the actual device. The song list and practice prompts are not supplied; obtaining those contents blocks populating the aid, but does not change the agreed flow. No offline-availability promise is made by the storage choice.

### Behavior and copy

Choose a song → see its short practice prompt → optionally mark today's attempt → see the seven calendar days ending today. Marking an attempt is repeat-safe: another tap does not create another mark for that song and date. Use the tablet's local calendar date as an agent default; device clock accuracy is assumed.

| State | Visible text and behavior |
|---|---|
| Song choice | “Choose a song”; song titles preserve supplied wording. |
| Ready | Show the chosen song and practice prompt; action: “Mark today's attempt”. |
| Marked | “Attempt recorded for today”; allow changing the song. |
| History | “Last seven days”; mark recorded attempts, with “No attempt recorded” for an unmarked day. No failure colors, streaks or scores. |
| First use | “Your practice days will appear here.” |
| Storage failure | “Today's attempt couldn't be saved. You can still practise.” Offer “Try again”. Do not show a saved confirmation. |

Accessible labels must express the date and whether an attempt was recorded, without relying on color. Dates use the tablet's locale; keep strings separate from behavior so wording and translation can be changed safely.

### Examples and validation

- With a supplied song selected, its prompt appears without sign-in or assistance.
- Recording today's attempt updates that song's history once; tapping again does not duplicate it.
- Missing yesterday leaves an unmarked day and no judgmental message.
- Reloading with available storage retains the records; losing local storage returns to first-use state without blocking practice.
- A failed write shows the recovery message and does not claim success.

Verify these examples on the actual tablet, including readable text and comfortable touch controls. Accounts, synchronization, scores, notifications, streaks and a broader music library are deferred.

### Behavior: Resume tour

On the home screen, show one “Resume tour” action when the progress store identifies a last unfinished tour. Activating it opens that tour at its last played stop. When there is no unfinished tour, the action is absent. The action works offline and must not modify downloaded audio or saved progress.

Use the existing progress store and matching home-screen action pattern in the native iOS SwiftUI app. The current approved frontend packet governs the exact appearance and states; no new visual exploration is required.

### Acceptance examples

- Given an unfinished tour whose last played stop is stop 4, activating “Resume tour” opens that tour at stop 4.
- Given several tours with progress, resume the last unfinished tour identified by the existing progress store, rather than a completed tour.
- Given no unfinished tour, the home screen has no “Resume tour” action.
- Given the device is offline, the same unfinished tour opens at the saved stop using the existing offline guide behavior.
- Before and after using the action, downloaded audio and saved progress are unchanged by the resume action itself.
