# Décision proposée

Retenir **A, en dialogue compact avec validation au fil de la saisie**. Le parcours principal reste sur un seul écran : montant positif, sens de l’ajustement, parking, motif, note et confirmation, puis **Enregistrer**. **Prévisualiser** reste une action secondaire et facultative ; sa consultation ne conditionne jamais l’enregistrement.

Ne pas adopter maintenant le panneau de revue de B. Il répète des informations et ajoute une étape sans preuve qu’elle améliore le travail répété. L’avis du responsable justifie un prototype ou un test chronométré ultérieur pour les usages fréquents, pas une modification du parcours actuel. Le panneau approuvé dans l’outil d’entrepôt ne constitue pas un précédent applicable : ce contexte impose une comparaison répétée de totaux, absente ici.

# Texte français

**État normal**

- Titre : « Ajuster le solde »
- Sous-titre : « Cette opération sera enregistrée dans l’historique. »
- Montant : « Montant » ; aide : « Saisissez un montant positif. »
- Sens : « Créditer » / « Débiter »
- Parking : « Parking »
- Motif : « Motif »
- Note : « Note obligatoire »
- Confirmation : « Je confirme que les informations sont exactes. »
- Actions : « Prévisualiser » / « Enregistrer l’ajustement » / « Annuler »

**Prévisualisation**

« Vérifiez l’ajustement avant de l’enregistrer. La prévisualisation est facultative. »  
Action principale : « Enregistrer l’ajustement » ; retour : « Modifier ».

**Succès**

« Ajustement enregistré. Nouveau solde : {nouveau solde}. »  
Action : « Fermer ».

**Refus**

« L’ajustement n’a pas été enregistré. Vérifiez les informations ou contactez l’assistance avec la référence {correlationId}. »  
Actions : « Vérifier les informations » / « Copier la référence ».

**Résultat incertain**

« Impossible de confirmer l’enregistrement. L’ajustement a peut-être été appliqué. Réessayez sans modifier les informations ou contactez l’assistance avec la référence {correlationId}. »  
Actions : « Réessayer » / « Copier la référence » / « Fermer ».

# Éléments à conserver ou retirer

**Conserver :** sous-titre d’audit en langage métier ; montant positif ; crédit/débit ; solde actuel ; identité client ; parking ; motif ; note obligatoire ; confirmation ; prévisualisation facultative ; enregistrement direct ; nouveau solde au succès ; référence d’assistance lorsqu’une investigation est utile.

**Retirer du dialogue opérateur :** montant signé près du champ et sa répétition dans une revue ; panneau de revue permanent ; compteur de caractères sans limite ; noms techniques `status`, `writeAudit`, `TRANSPORT_FAILURE`, `retryKey` et libellé brut `correlationId`. Le `retryKey` et l’identité stable restent internes.

La console support conserve la recherche par identifiant de corrélation. L’opérateur voit seulement une « référence d’assistance » copiable dans les états refusé ou incertain ; l’ingénieur retrouve ensuite l’incident dans cette console.

# Handoff implémentation et vérification

Implémenter A avec validation inline, un bouton de prévisualisation secondaire, et le même chemin d’enregistrement avec ou sans prévisualisation. Mapper les réponses techniques vers les quatre états ci-dessus et préserver l’identité stable lors d’une relance inchangée.

Vérifier : saisie complète et erreurs inline ; enregistrement sans prévisualisation ; prévisualisation puis modification ; succès et affichage du nouveau solde ; refus ; timeout puis relance inchangée ; copie et recherche de la référence dans la console support ; absence de champs techniques et de doublons visuels. Tester rapidement avec des opérateurs occasionnels et fréquents avant de réexaminer B.
