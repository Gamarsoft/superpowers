# Décision proposée

Retenir le design A pour cette révision : un formulaire compact, avec validation au fil de la saisie et un récapitulatif court intégré avant les actions. Ne pas ajouter le panneau de revue séparé de B. L'usage répété reste une piste à tester avec des opérateurs ; l'absence d'étude de temps ou de performance ne permet pas d'affirmer que B serait plus efficace.

Le panneau latéral approuvé dans l'outil d'entrepôt ne doit pas être transposé ici. Il répond à une tâche différente, où les opérateurs comparent des totaux de manière répétée. Cette approbation valide ce cas précis, pas un nouveau modèle général.

# Copie française

**État normal**

- Titre : « Ajuster le solde »
- Montant : « Montant » — aide : « Saisissez un montant positif. »
- Type : « Crédit » / « Débit »
- Parking : « Parking »
- Motif : « Motif »
- Note : « Note » — aide : « Obligatoire »
- Récapitulatif intégré : « Vous allez créditer/débiter {montant} sur le solde de {client}, pour le parking {parking}. Motif : {motif}. »
- Actions : « Prévisualiser » et « Enregistrer l’ajustement »

**Confirmation**

Case obligatoire : « Je confirme que le montant, le type d’ajustement, le parking et le motif sont corrects. »

**Prévisualisation**

Titre : « Prévisualisation de l’ajustement »

Texte : « Aucun ajustement n’a encore été enregistré. Vérifiez les informations ci-dessous, puis enregistrez lorsque vous êtes prêt. »

Action principale : « Enregistrer l’ajustement » ; action secondaire : « Modifier ».

**Succès**

« Ajustement enregistré. Nouveau solde : {nouveau solde}. »

**Refus**

« L’ajustement n’a pas été enregistré. Vérifiez les informations saisies, puis réessayez. »

**Résultat incertain**

« Nous n’avons pas pu confirmer l’enregistrement. L’ajustement a peut-être été appliqué. Vous pouvez réessayer sans modifier les informations ; la même demande ne sera pas appliquée deux fois. Si le doute persiste, contactez l’assistance. »

# Éléments à conserver ou retirer

**Conserver :** montant positif, choix crédit/débit, parking, motif, note obligatoire, confirmation, solde actuel, identité du client, prévisualisation facultative, enregistrement accessible sans prévisualisation, nouveau solde après succès et sous-titre d’audit s’il explique clairement la traçabilité à l’opérateur.

**Retirer de l’interface opérateur :** montant signé répété près du champ et dans un panneau, panneau de revue séparé, compteur de caractères sans limite, `status=accepted`, `writeAudit=true`, `TRANSPORT_FAILURE`, `retryKey` et les libellés techniques de réponse. Afficher le montant signé une seule fois dans le récapitulatif intégré.

Le `correlationId` sert au diagnostic : le journaliser et le rendre recherchable dans la console d’assistance, avec les autres champs techniques utiles aux ingénieurs. Il ne doit pas encombrer le parcours normal ; l’assistance peut le retrouver depuis l’incident enregistré.

# Handoff d’implémentation et de vérification

Mettre à jour la maquette avec A, les textes ci-dessus et les cinq états. Vérifier : validation d’un montant positif et d’une note présente ; confirmation obligatoire ; sauvegarde possible sans prévisualisation ; montant affiché une seule fois ; succès avec nouveau solde ; refus sans jargon ; timeout traité comme incertain ; nouvelle tentative inchangée conservant l’identité stable ; données techniques absentes du dialogue et disponibles dans la console via le `correlationId`. Faire ensuite tester A et B sur des séries d’ajustements répétés avant toute décision sur B.
