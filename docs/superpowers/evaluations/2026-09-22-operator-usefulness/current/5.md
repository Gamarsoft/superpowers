# Décision proposée

Explorer une version B resserrée pour le travail répété : formulaire à gauche, récapitulatif fixe à droite dans la même boîte de dialogue. Le récapitulatif sert à vérifier l'effet avant enregistrement, sans créer une étape obligatoire. Il montre une seule fois l'effet signé (`+ 25,00 €` ou `− 25,00 €`), le solde actuel, le client, le parking, le motif et la note. L'entrée reste un montant positif ; le choix **Crédit / Débit** détermine le signe.

Le bouton **Voir l’aperçu** reste secondaire et facultatif ; **Enregistrer l’ajustement** est disponible dès que les champs et la confirmation requise sont valides. Cette proposition doit être testée face à A sur des séries d'ajustements, notamment pour les erreurs de sens crédit/débit, la relecture et l'encombrement. En l'absence d'étude, ne pas présenter B comme plus rapide.

Le panneau latéral approuvé dans l'outil d'entrepôt ne vaut pas approbation ici : il maintient côte à côte des totaux comparés de façon répétée. Ici, le panneau synthétise une seule opération. Il constitue une hypothèse de conception propre à ce dialogue.

# Texte français

**État normal**

- Titre : **Ajuster le solde**
- Champs : **Montant**, **Type d’ajustement**, **Crédit**, **Débit**, **Parking**, **Motif**, **Note**
- Aide montant : **Saisissez un montant positif. Le type d’ajustement détermine son effet sur le solde.**
- Récapitulatif : **Effet sur le solde**, **Solde actuel**, **Client**, **Parking**, **Motif**, **Note**
- Actions : **Annuler**, **Voir l’aperçu**, **Enregistrer l’ajustement**

**Confirmation**

- Case : **Je confirme que les informations de cet ajustement sont exactes.**

**Aperçu**

- Titre : **Aperçu de l’ajustement**
- Aide : **Vérifiez l’effet sur le solde. Vous pouvez encore modifier les informations.**
- Actions : **Modifier**, **Enregistrer l’ajustement**

**Succès**

- Titre : **Ajustement enregistré**
- Message : **Le nouveau solde est de {newBalance}.**
- Action : **Fermer**

**Refusé — non appliqué**

- Titre : **Ajustement non enregistré**
- Message : **L’ajustement a été refusé. Vos informations sont conservées ; vérifiez-les avant de réessayer.**
- Actions : **Corriger**, **Fermer**

**Résultat incertain après expiration du délai**

- Titre : **Résultat de l’enregistrement incertain**
- Message : **Nous ne pouvons pas confirmer si l’ajustement a été enregistré. Réessayez à l’identique pour éviter un doublon. Si le doute persiste, contactez l’assistance.**
- Actions : **Réessayer à l’identique**, **Fermer**

# Éléments à conserver ou retirer

**Conserver :** solde actuel ; nom et identifiant client ; parking ; motif ; note requise ; confirmation ; aperçu facultatif ; effet signé, une seule fois dans le récapitulatif ; nouveau solde après succès. Afficher **Référence d’assistance : {correlationId}** seulement dans un état qui fournit réellement cet identifiant.

**Retirer de l'interface opérateur :** sous-titre d'audit ; effet signé en double ; compteur de caractères sans limite ; `status=accepted`, `writeAudit=true`, `TRANSPORT_FAILURE` et `retryKey`. Ces données techniques restent dans la télémétrie. La console ingénieur reste séparée. Le contrat d’expiration fourni ne contient pas de `correlationId` : ne pas déguiser `retryKey` en référence d’assistance. Relier cet incident à la recherche par corrélation est une question produit/technique non résolue, hors de cette révision.

# Handoff d’implémentation et de vérification

Prototyper B avec le contenu ci-dessus, sans modifier les règles métier. Vérifier : montant positif et mapping crédit/débit ; unicité du montant signé ; enregistrement sans aperçu ; validation des champs et de la confirmation ; conservation des saisies après refus et résultat incertain ; nouvelle tentative strictement identique ; format monétaire français ; libellés complets au clavier et par lecteur d'écran ; repli du panneau sous le formulaire en largeur étroite. Comparer A et B sur des tâches répétées sans conclure à un gain de performance avant observation.
