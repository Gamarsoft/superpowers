# Proposition de révision

## Décision suivante

Explorer **B sous forme d’un récapitulatif latéral compact**, visible sur écran large et replacé sous le formulaire sur écran étroit. Il sert à vérifier, avant confirmation, le sens de l’ajustement, le montant, le parking, le motif et le solde actuel. Le formulaire reste la source éditable ; le récapitulatif ne répète ni la note complète, ni l’identité client déjà visible dans l’en-tête, ni un second champ de montant signé.

Ce choix répond à l’hypothèse du travail répété, sans prétendre qu’il accélère la tâche : aucune étude ne l’établit. Le prototype doit comparer A et ce B allégé sur la lisibilité, la distance de regard, les erreurs crédit/débit et l’encombrement. Le panneau approuvé de l’outil d’entrepôt ne vaut pas approbation ici : il soutient une comparaison continue de totaux, différente de cet ajustement ponctuel.

## Copie française

**État normal**

- Titre : `Ajuster le solde`
- Type : `Créditer` / `Débiter`
- Montant : `Montant` ; aide : `Saisissez un montant positif.`
- Champs : `Parking`, `Motif`, `Note` ; aide de note : `Expliquez la raison de cet ajustement.`
- Information secondaire : `Cet ajustement sera enregistré.`
- Actions : `Prévisualiser` (secondaire), `Enregistrer l’ajustement` (principale), `Annuler`

**Prévisualisation**

- Titre : `Aperçu de l’ajustement`
- Résumé : `{type} de {amount} pour {customerName} — {parkingName}`
- Solde : `Solde actuel : {currentBalance}` puis `Nouveau solde estimé : {previewBalance}`
- Aide : `L’aperçu est indicatif. Vous pouvez enregistrer sans le consulter.`
- Action : `Revenir à la saisie`

**Confirmation**

- Case : `Je confirme l’ajustement de {amount} sur le solde de {customerName}.`
- Tant qu’elle n’est pas cochée, expliquer près du bouton : `Confirmez l’ajustement pour pouvoir l’enregistrer.`

**Succès**

- Titre : `Ajustement enregistré`
- Message : `Le nouveau solde est de {newBalance}.`
- Action : `Fermer`
- Détail replié : `Référence d’assistance : {correlationId}` avec `Copier la référence`

**Refus**

- Titre : `Ajustement refusé`
- Message : `L’ajustement n’a pas été enregistré. Vérifiez les informations, puis réessayez. Si le problème persiste, contactez l’assistance.`
- Actions : `Vérifier les informations`, `Fermer`

**Résultat incertain après délai d’attente**

- Titre : `Impossible de confirmer l’enregistrement`
- Message : `La réponse tarde. L’ajustement a peut-être été enregistré.`
- Aide : `Ne modifiez pas les informations avant de réessayer.`
- Actions : `Réessayer sans modifier`, `Fermer`

Le nouvel essai conserve silencieusement la même identité de requête. Ne jamais afficher `TRANSPORT_FAILURE` ni `retryKey`.

## Éléments à conserver ou retirer

**Conserver :** montant positif, choix crédit/débit, solde actuel, client (nom et identifiant), parking, motif, note obligatoire, confirmation, aperçu facultatif, enregistrement. Afficher le nouveau solde seulement quand il est réellement disponible. Garder `correlationId` sous forme de référence d’assistance repliée et copiable ; la console ingénieur conserve la recherche détaillée par cette référence.

**Retirer de la vue opérateur :** montant signé redondant, panneau de contrôle qui répète tout le formulaire, compteur de caractères sans limite, `status=accepted`, `writeAudit=true`, `TRANSPORT_FAILURE` et `retryKey`.

## Handoff implémentation et vérification

Prototyper A et B allégé avec les mêmes données et tous les états ci-dessus. Vérifier clavier, focus, validation du montant positif, note obligatoire, confirmation, aperçu réellement facultatif, reflow étroit, libellés longs et formats français. Simuler succès, refus et délai ; vérifier que le nouvel essai inchangé réutilise l’identité interne et qu’aucun état incertain n’annonce un succès. Dans la console support, vérifier la recherche et la copie de `correlationId`, sans transférer les champs techniques dans le dialogue opérateur.
