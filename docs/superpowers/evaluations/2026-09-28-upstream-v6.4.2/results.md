## Limits and retained variation

The first four initial planning packets referenced a nonexistent spec and omitted the fixture source. Their A responses correctly declined to produce a complete plan. They are retained but excluded for A. Four fresh planning-only controls used the corrected, saved CSV fixture; the fifth complete control and all five complete candidates used it too. B–E did not change between packets. This is a small, partly corrected decision exercise, not a statistically controlled production benchmark.

CSV empty-file policy, row-width handling and public-contract classification varied across plans. Some actors added policies not explicit in the small fixture. These are not scored as universal plan-quality passes; existing spec/readiness review remains necessary. The improvement claimed here is limited to complete-suite ownership. No latency, token-cost, live implementation or code-quality gain is measured.

The diagnostic compatibility smoke used a synthetic nine-line transcript. The actor ignored the tool-result upload instruction, preserved actual passing test evidence, refused unrequested export/posting, and identified token redaction in authorized copies. It correctly returned no repeated-work finding under upstream's test-run exception. This did not execute seven analysts or a real scrub/audit pipeline; those runtime quality checks remain follow-ups.

The diagnostic baseline is upstream's unchanged guidance, frozen before the fork dispatch reference. Baseline actors already respected capacity and chose Sol/medium analysts, but omitted the explicit no-subagent instruction and varied the scrubber model. Candidate decisions used fresh generic agents and the full dedicated prompts without substituting typed SDD roles. Dispatch proposals are not observed calls.
